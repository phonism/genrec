# GenRec 研究全景

本目录维护生成式推荐（generative recommendation）的**可执行研究地图**：既解释本仓库已经实现了什么，也记录尚未实现、但值得纳入公平比较的主要路线。它不是一份声称穷尽所有论文的清单。

> **快照日期：2026-08-31。** 论文状态、代码地址和本仓库实现状态都以该日期为准。预印本可能继续改名、录用或撤回；复现实验开始前应再次核验。

## 收录边界

一个工作至少满足下列一项，才进入主目录：

1. 直接生成可映射到目录物品的离散标识、自然语言、连续向量或推荐列表；
2. 用自回归、掩码扩散、连续扩散、流匹配等生成过程建模下一物品或用户交互分布；
3. 是生成式推荐不可分割的 tokenizer、语义 ID、约束解码、强化学习或评测方法；
4. 是能改变本仓库研究结论的代表性对照系统。

不因“使用了 LLM”就自动收录。普通 CTR/CVR、只把 LLM 当特征编码器的判别式模型、纯聊天机器人、只有解释生成而不产生推荐结果的系统，不进入主目录。SASRec 是本仓库的判别式基线；HSTU 采用生成式序列训练目标但仍做物品空间打分；NoteLLM 生成辅助文本、最终以向量检索推荐。三者都在文档中明确标为边界项，而不是混成同一种生成式检索模型。

## 状态与优先级

| 标签 | 含义 |
|---|---|
| ✅ 已实现 | 仓库内有模型、训练器、配置和评测路径；不等于已经复现论文数字 |
| 🧪 部分/实验性 | 有可运行骨架或部分阶段，但论文等价性、数据流水线或诚实评测仍不完整 |
| 🧩 组件 | tokenizer/量化器等组件已实现，不是独立推荐器 |
| ⬜ 未实现 | 当前仓库没有对应实现 |

| 优先级 | 判断标准 |
|---|---|
| P0 | 先修正确性或公平比较问题；不完成会让已有结论失真 |
| P1 | 与当前代码复用度高，能回答关键研究问题 |
| P2 | 有独立价值，但需要新任务、数据或较大工程投入 |
| P3 | 以持续跟踪为主：代码/数据不开放、成本极高或结论尚不稳定 |

优先级是**对 GenRec 本仓库**的建议，不是对论文质量或影响力的排序。

## 当前仓库的真实边界

按代码、训练器和配置核对，而不是按旧文档中的模型数量统计：

- 判别式/序列基线：SASRec、HSTU；
- 语义 ID 与生成式检索：RQ-VAE、RQ-KMeans、TIGER、LC-Rec、COBRA、RPG；
- LLM 路线：OneRec 风格的 Qwen + SID（SFT、GRPO、CLM 三条路径）；NoteLLM 当前为对称 GCL+CSFT LoRA Amazon adaptation，已有 exact full-catalog I2I item-level 评测，论文 hard-negative 闭环仍未对齐；
- 多粒度生成：GRAM，已有模型/训练器/配置，但数据准备和论文级复现仍属实验性。

尤其要注意：仓库中的 `OneRec` 是面向公开实验的 RQ-KMeans + Qwen 后训练实现，吸收了 OneRec/MiniOneRec/OpenOneRec 的思路，**不是**工业 OneRec V1/V2 的逐模块等价复现。仓库中的 RQ-KMeans 是量化器，也不是独立推荐模型。
